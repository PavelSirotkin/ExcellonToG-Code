# ExcellonToG-Code

[![Python](https://img.shields.io/badge/Python-3.8%2B-blue.svg)](https://www.python.org/)
[![Tests](https://img.shields.io/badge/Tests-427%20passing-brightgreen.svg)](tests/)
![Лицензия](https://img.shields.io/badge/license-free-green.svg)
![Версия](https://img.shields.io/badge/version-5.5-orange.svg)

**Конвертация Excellon-файлов (сверление PCB) в G-code для любительских ЧПУ-станков с поддержкой слотов, импорта контура из Gerber и финишной обрезки платы по контуру произвольной формы.**

ExcellonToG-Code — это desktop-приложение на Python + Tkinter для подготовки управляющей программы ЧПУ-сверлилки/фрезера из выходных файлов PCB CAD (KiCad, EasyEDA, Altium и т.п.). На вход подаются Excellon-файлы сверления и опционально Gerber-контур платы, на выходе получается готовый `.tap/.gcode/.nc/.ngc` с оптимизированным маршрутом, многопроходной фрезеровкой слотов и финишной обрезкой по контуру произвольной формы (включая внутренние вырезы) с держательными перемычками (tabs).

Приложение полностью автономно: никаких внешних зависимостей кроме стандартной библиотеки Python. Парсеры Excellon и Gerber, TSP-оптимизация маршрута, геометрия полигонов, генератор G-code и 2.5D-визуализатор — всё написано на чистом Python без numpy/scipy/shapely.

## 🎯 Возможности

### Входные данные
- **Excellon RoundHoles** (`.TXT`, `.DRL`) — круглые сверления
- **Excellon SlotHoles** (`.TXT`, `.DRL`) — овальные отверстия (слоты) с парой координат
- **Gerber RS-274X** (`.GBR`, `.G`, `.GBP`) — контур платы (edge-cuts)
- Автоопределение формата координат (2.4, 3.3, 4.2) и единиц (мм / дюймы)
- Предупреждение при загрузке файлов с несовместимыми форматами

### Обработка маршрута
- **TSP-оптимизация** порядка обхода отверстий: Nearest Neighbor + 2-opt
- Отдельная оптимизация слотов с учётом точек входа/выхода (какой конец слота ближе)
- Группировка по инструментам (минимум смен сверла)
- Минимизация холостых перемещений (rapid)

### Генерация G-code
Четыре независимых режима генерации:

| Кнопка | Что генерирует |
|---|---|
| **G-код сверления** | Только круглые отверстия (по секциям инструментов) |
| **G-код фрезеровки** | Только слоты (многопроходная фрезеровка) |
| **G-код обрезки** | Только финишную обрезку платы по Gerber-контуру |
| **Объединённый G-код** | Всё в одном файле: сверление → слоты → контур |

Особенности генерации:
- `M00` — пауза для смены инструмента с комментарием о следующем диаметре
- `M03 S{RPM}` / `M05` — включение/выключение шпинделя (режим «Про»)
- Настраиваемые подачи: `feed_rate` (погружение Z), `mill_feed` (резка XY), `rapid_rate` (холостой)
- Безопасная `safe_z`, рабочая `drill_z`, парковочная `park_z`
- Валидация параметров перед генерацией с понятными сообщениями об ошибках

### Финишная обрезка платы
Отдельная секция G-code с полным циклом обрезки:

- **Поддержка контуров произвольной формы** — внешний контур и внутренние вырезы
- **Автоматическое определение типа контура** — внешние контуры и внутренние вырезы распознаются автоматически
- **Умный offset** — наружу для внешних контуров, внутрь для внутренних вырезов
- **Многопроходная Z-фрезеровка** с шагом `depth_per_pass` до `drill_z`
- **Порядок обработки** — внутренние вырезы фрезеруются первыми (плата жёстко удерживается заготовкой), внешний контур — последним (отделение детали через tabs)
- **Безопасное первое погружение** — старт каждого прохода смещается в середину самого длинного non-tab участка, чтобы фреза не срезала перемычку при плонже
- **Держательные перемычки (tabs)**: только на внешних контурах, строго в середины сторон (не на углы)
- **Параметры tabs**: ширина моста `tab_width`, высота моста `tab_height` (фреза не выходит полностью — оставляет материал)
- **Направление обхода**: CW / CCW (на выбор)
- **Валидация попадания отверстий внутрь контура** — точки вне контура подсвечиваются красным, но генерацию не блокируют
- **Поддержка KiCad Edge.Cuts** — автоматическая сшивка штрихов в замкнутые контуры

### Режимы работы

#### 🔧 Простой
Все параметры задаются глобально (подача, глубина, безопасная высота, RPM). Идеально для разовых задач и начинающих.

#### ⚙ Про
Полноценная база инструментов:
- Отдельные параметры на каждый диаметр: `spindle_speed`, `plunge_feed`, `retract_feed`
- **Доп. глубина (`extra_depth`)** для сверл — индивидуальный оверрайд глубины конкретного сверла относительно глобального `drill_z` (например, сверло 3 мм идёт на 1 мм глубже остальных)
- Автоподбор параметров из базы при генерации
- Предупреждение об отсутствующих в базе диаметрах
- Редактор базы с импортом/экспортом JSON (`tool_base.json`)

### Интерфейс

#### 🌙 Тёмная тема
- Поддержка светлой и тёмной цветовых тем
- Переключатель темы в правой панели настроек (группа «Вид»)
- Выбранная тема сохраняется и восстанавливается при следующем запуске
- Автоматическая перерисовка всех элементов интерфейса при смене темы без перезапуска

#### 🌐 Английская локализация
- Поддержка двух языков: русский (по умолчанию) и английский
- Переключатель языка в правой панели настроек (🌐 RU / EN)
- Выбранный язык сохраняется в настройках
- Переведены все элементы UI: меню, кнопки, диалоги, подсказки, справка, база инструментов
- Автоматическое обновление интерфейса при смене языка без перезапуска приложения

### Визуализация и статистика
- **2.5D-кабинетная проекция** — квази-трёхмерный вид процесса обработки с глубиной
- **Плеер** — пошаговое воспроизведение с регулировкой скорости и паузой
- **Интерактивная легенда** — фильтрация по инструментам, solo-режим, подсветка при наведении
- **Подсказки** — координаты, диаметр, тип операции при правом клике на элементе
- **Отображение tabs** — участки над перемычками выделены цветом на визуализации
- **📊 Полноценная статистика проекта** — детальная информация о плате, инструментах, путях и времени обработки с визуальным оформлением и возможностью копирования в буфер обмена

## ⚡ Установка

### Требования
- **Python 3.8+** (проверено на 3.8 – 3.14)
- **Tkinter** (входит в стандартный дистрибутив Python; на Linux может потребоваться отдельно: `sudo apt install python3-tk`)
- **ОС**: Windows, Linux, macOS

### Установка из исходников

```bash
# 1. Клонируем репозиторий
git clone https://github.com/PavelSirotkin/ExcellonToG-Code.git
cd ExcellonToG-Code

# 2. Запускаем
python main.py
```

Всё — никаких `pip install` для запуска приложения не нужно.

### (Опционально) Зависимости для разработки

Для запуска тестов:

```bash
pip install -r requirements-dev.txt
```

В `requirements-dev.txt` только `pytest` и `pytest-cov`.

### (Опционально) Сборка exe для Windows

В корне есть готовый spec-файл PyInstaller:

```bash
pip install pyinstaller
pyinstaller ExcellonToG-Code.spec
```

Результат — один `.exe` в папке `dist/`.

## 🚀 Быстрый старт

### Сценарий 1 — только сверление

1. Запустите `python main.py`.
2. **«📂 Открыть Excellon»** — выберите `.drl` или `.txt` файл сверления (пример: `Samples/HLDI_ALL_PCB-[HLDI Main].DRL`).
3. На canvas появятся круги разных цветов — каждый цвет соответствует своему диаметру. Легенда справа показывает диаметры и число отверстий.
4. Двойной клик на canvas — автомасштабирование.
5. Отредактируйте параметры в блоке «Параметры G-кода» (значения автосохраняются в `gcode_params.json` при потере фокуса).
6. **«⚙ G-код сверления»** — сохраните `.tap`-файл.

### Сценарий 2 — сверление + слоты + обрезка

1. **«📂 Открыть Excellon»** → файл RoundHoles (`Материнка универсальная-RoundHoles.TXT`).
2. **«📂 Открыть SlotHoles»** → файл слотов (`Материнка универсальная-SlotHoles.TXT`).
3. **«📂 Открыть Board Outline (Gerber)»** → контур платы (`Материнка универсальная_Profile.gbr`).
4. На canvas видны:
   - Круги (отверстия, цвет по диаметру)
   - Слоты (овалы)
   - Контур платы (тёмно-серая линия)
   - Красные кружочки вокруг отверстий, выпавших за контур (если есть)
5. В блоке «Обрезка по контуру» задайте: диаметр фрезы, глубину за проход, число перемычек, их ширину и высоту, направление обхода.
6. **«⚙ Объединённый G-код»** — получите один `.tap`-файл со всеми тремя секциями: сверление → слоты → обрезка.

### Сценарий 3 — проверить перед отправкой на станок

1. После генерации нажмите **«🎬 Визуализация G-code»** (появляется как только сгенерирован хотя бы один файл).
2. Откроется 2.5D-просмотр. Используйте плеер для пошагового воспроизведения.
3. Легенда сбоку — включайте/выключайте отдельные инструменты.
4. Убедитесь, что tabs выделены цветом и стоят в ожидаемых позициях.

### Сценарий 4 — смена темы и языка

1. В правой панели настроек найдите группу «Вид» (или «View» на английском).
2. Используйте переключатель **🌙 Светлая / Тёмная** для смены цветовой темы.
3. Используйте переключатель **🌐 RU / EN** для смены языка интерфейса.
4. Все изменения применяются мгновенно без перезапуска и сохраняются для следующего сеанса.

## ⚙ Параметры G-code

Хранятся в `gcode_params.json` (автоматически создаётся при первом изменении).

### Основные параметры

| Параметр | Описание | Типичное значение |
|---|---|---|
| `safe_z` | Безопасная высота Z для холостых перемещений (мм) | `5.0` |
| `drill_z` | Рабочая глубина сверления/фрезеровки (мм, отрицательная) | `-2.5` |
| `feed_rate` | Подача при погружении Z (мм/мин) | `100` |
| `mill_feed` | Подача при резке XY (мм/мин) | `50` |
| `rapid_rate` | Скорость холостых перемещений (мм/мин) | `500` |
| `park_z` | Высота парковки после завершения (мм) | `30.0` |

### Параметры обрезки

| Параметр | Описание | Типичное значение |
|---|---|---|
| `outline_tool_diameter` | Диаметр фрезы для обрезки (мм) | `2.0` |
| `outline_depth_per_pass` | Глубина за проход по Z (мм) | `0.5` |
| `outline_n_tabs` | Количество держательных перемычек | `4` |
| `outline_tab_width` | Ширина перемычки по дуге контура (мм) | `2.0` |
| `outline_tab_height` | Высота оставляемого моста (мм) | `1.0` |
| `outline_direction` | Направление обхода: `CCW` / `CW` | `CCW` |

### База инструментов (`tool_base.json`)

Используется только в режиме «Про». Содержит словари `drills` и `endmills` с параметрами на каждый диаметр:

```json
{
  "drills": {
    "0.45": {
      "diameter": 0.45,
      "spindle_speed": 20000,
      "plunge_feed": 100.0,
      "retract_feed": 500.0,
      "extra_depth": 0.0
    },
    "3.0": {
      "diameter": 3.0,
      "spindle_speed": 15000,
      "plunge_feed": 200.0,
      "retract_feed": 500.0,
      "extra_depth": 1.0
    }
  },
  "endmills": { ... }
}
```

`extra_depth` (мм, по умолчанию 0) — положительное значение делает сверло глубже глобального `drill_z` на указанную величину. Поле опционально: legacy-записи без него работают как `extra_depth = 0`.

Редактируется через GUI: **«🗄 База инструментов»** (видимая в режиме «Про»).

### Принципы архитектуры

- **Разделение core/ui** — `core/` не знает о Tkinter и может быть переиспользован в CLI/web-интерфейсе или как библиотека. `ui/` обращается к `core/` напрямую, но не наоборот.
- **Модульная структура UI** — `ui/app.py` разбит на логические модули: `panels/` (компоненты интерфейса) и `handlers/` (обработчики событий). Основной файл сократился с 1363 до ~700 строк.
- **Dependency Injection** — использование `AppContext` для управления зависимостями вместо глобальных переменных, что упрощает тестирование и поддержку.
- **Глобальное состояние в `core/config.py`** — единый `cfg`-объект с загруженными отверстиями, слотами, контуром, активным режимом и реестром GUI-виджетов (по строковым ключам, чтобы модули UI не тянули друг друга).
- **Система тематизации** — семантические палитры цветов с автоматическим обновлением всех зарегистрированных виджетов при смене темы.
- **Система локализации** — централизованная система переводов с поддержкой динамического переключения языка и параметризованных строк.
- **Полные type hints** — все модули используют полную типизацию для улучшения статического анализа и IDE-поддержки.
- **Чистые функции в геометрии** — `polygon_ops.py` и `tsp_optimizer.py` не имеют побочных эффектов, легко тестируются.
- **Ноль внешних зависимостей** для runtime-кода — политика проекта, подтверждённая в `requirements-dev.txt`.

## 📄 Форматы файлов

### Входные

| Формат | Расширения | Что содержит |
|---|---|---|
| Excellon (RoundHoles) | `.TXT`, `.DRL` | Круглые сверления: инструменты + координаты |
| Excellon (SlotHoles) | `.TXT`, `.DRL` | Овальные отверстия: пары координат (начало-конец) |
| Gerber RS-274X | `.GBR`, `.G`, `.GBP` | Контур платы (edge-cuts): G01 линии + G02/G03 дуги |

#### Поддерживаемое подмножество Gerber

- `%FSLAX..Y..*%` — формат координат (leading zeros, absolute)
- `%MOMM*%` / `%MOIN*%` — единицы: мм или дюймы (дюймы конвертируются)
- `G01` / `G02` / `G03` — линейная / по часовой / против часовой интерполяция
- `G36` / `G37` — режим региона (замкнутый контур, внутренние вырезы)
- `G75` — multi-quadrant arc mode (KiCad)
- `X..Y..D01*` — резка (линия или дуга с I/J)
- `X..Y..D02*` — move без резки
- `M02*` — конец файла
- Апертуры (`%ADD...*%`, `Dnn*`) игнорируются — на контур не влияют
- **Автоматическая сшивка штрихов** — KiCad Edge.Cuts экспортирует контур отдельными штрихами, программа автоматически собирает их в замкнутые контуры

### Выходные

| Формат | Расширения | Назначение |
|---|---|---|
| G-code | `.tap`, `.gcode`, `.nc`, `.ngc` | Управляющая программа ЧПУ |
| JSON | `gcode_params.json` | Сохранённые параметры G-code |
| JSON | `tool_base.json` | База инструментов (режим «Про») |
| JSON | `app_settings.json` | Настройки приложения (тема, язык) |

## 🐛 Известные ограничения

- **Gerber**: поддержано минимальное подмножество RS-274X, достаточное для outline-файлов KiCad / EasyEDA / Altium. Сложные апертуры, макросы, трассировка не нужны (парсер читает только геометрию контура).
- **Offset внешних углов**: простое пересечение смещённых рёбер. Острые углы снаружи остаются острыми (фреза не скругляет).
- **Inch-формат Gerber**: поддержан через `%MOIN*%`, но реальные файлы в дюймах не тестировались массово.
- **TSP 2-opt** — жадный эвристический алгоритм, не гарантирует глобального оптимума. На типичных платах (100-500 отверстий) сходится за 10-50 итераций и даёт решение близкое к оптимуму.
