**Дата:** Май 2026

Этот релиз добавляет per-tool оверрайд глубины сверления в Pro-режиме и закрывает критический баг с потерей перемычки при первом погружении фрезы в обрезке по контуру.

---

## ✨ Новые функции

### 🛠 Доп. глубина сверления (Pro-режим)
В карточку сверла в базе инструментов добавлено поле **«Доп. глубина (мм)»** (`extra_depth`). Положительное значение делает сверло глубже глобального `drill_z` на указанную величину — например, сверло 3 мм может идти на 1 мм глубже мелких сверл без правки общего параметра. По умолчанию 0 — поведение не меняется.

Формула эффективной глубины при генерации drilling-секции:
```
effective_drill_z = drill_z - extra_depth
```

Параметр работает только в Pro-режиме и только для drills (фрезеровка слотов и обрезка контура не затрагиваются).

### 🔄 Изменён порядок обрезки контура
Внутренние вырезы и островки теперь фрезеруются **первыми**, внешний контур — **последним**. Раньше порядок был обратный.

Эффект: пока заготовка цельная, все точные операции (вырезы, островки) выполняются при максимальной жёсткости детали. Внешний контур режется в самом конце — деталь отделяется от заготовки и удерживается только tabs. Это соответствует стандартной CAM-практике и заметно улучшает точность контактных площадок и вырезов рядом с границей платы.

## 🐛 Исправления

### Срез держательной перемычки при первом погружении фрезы
В обрезке по контуру первое погружение фрезы происходило в `points[0]` исходного контура — точке, которая могла оказаться внутри tab-зоны (особенно при wrap-around tab-диапазона через начало контура). Фреза погружалась на полную глубину прямо в перемычку и срезала мост ещё до того, как остальные tabs были прорезаны.

Теперь старт каждого Z-прохода смещается в **середину самого длинного non-tab сегмента** — на максимальное удаление от любой tab-границы. Сегмент разбивается пополам в midpoint-точке M, замкнутый список сегментов поворачивается так, чтобы контур начинался и заканчивался в M. Форма траектории и расположение tabs не меняются — смещается только точка первого касания.

## 📦 Установка

### Из исходников
```bash
git clone https://github.com/PavelSirotkin/ExcellonToG-Code.git
cd ExcellonToG-Code
python main.py
```

Никаких runtime-зависимостей кроме стандартной библиотеки Python.

### Сборка exe (Windows)
```bash
pip install pyinstaller
pyinstaller ExcellonToG-Code.spec
```
Результат — один `.exe` в папке `dist/`.

## 🔄 Совместимость

- **Файлы конфигурации:** `gcode_params.json`, `tool_base.json`, `app_settings.json` — формат не меняется. Старые `tool_base.json` загружаются как есть.
- **G-code выход:** для старых проектов (не использующих Pro-режим, либо использующих базу без `extra_depth`) выход байт-в-байт идентичен v5.4. Изменение порядка обрезки контура — единственное наблюдаемое отличие в G-code, и оно срабатывает только при наличии внутренних вырезов в Gerber-контуре.
