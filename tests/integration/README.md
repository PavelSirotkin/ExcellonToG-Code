# Интеграционные тесты ExcellonToG-Code

Этот каталог содержит интеграционные тесты для проверки полного workflow приложения.

## Структура тестов

### 1. End-to-End тесты (`test_full_workflow.py`)
Тестируют полный цикл работы приложения от загрузки файла до генерации G-code.

**Покрытие:**
- ✅ Загрузка и парсинг Excellon файлов
- ✅ Загрузка и парсинг файлов слотов
- ✅ Парсинг Gerber контуров
- ✅ Генерация G-code для отверстий
- ✅ Генерация G-code для слотов
- ✅ Комбинированная генерация (отверстия + слоты)
- ✅ Работа с базой данных инструментов
- ✅ Обработка ошибок и валидация
- ✅ Автоопределение формата координат
- ✅ Проверка формата выходного G-code

**Запуск:**
```bash
pytest tests/integration/test_full_workflow.py -v
```

### 2. UI тесты (`test_ui_interaction.py`)
Тестируют взаимодействие пользователя с интерфейсом (требуют Tkinter).

**Покрытие:**
- ✅ Инициализация UI компонентов
- ✅ Переключение режимов (Simple/Pro)
- ✅ Валидация параметров G-code
- ✅ Операции с базой данных инструментов
- ✅ Симуляция загрузки файлов
- ✅ Переключение видимости инструментов
- ✅ Изменение формата координат
- ✅ Отображение сообщений
- ✅ Сбор статистики
- ✅ Переключение языка
- ✅ Создание подсказок
- ✅ Подготовка данных для визуализации
- ✅ Обработка ошибок в UI
- ✅ Работа с диалоговыми окнами

**Запуск:**
```bash
# Запустить все UI тесты
pytest tests/integration/test_ui_interaction.py -v -m gui

# Пропустить UI тесты (если Tkinter недоступен)
pytest tests/integration/test_ui_interaction.py -v -m "not gui"
```

### 3. Performance тесты (`test_performance.py`)
Тестируют производительность на больших файлах и экстремальных условиях.

**Покрытие:**
- ✅ Парсинг больших файлов (1000+ отверстий)
- ✅ Генерация G-code для больших плат
- ✅ TSP оптимизация (500 точек)
- ✅ Парсинг большого количества слотов (200+)
- ✅ Комбинированный workflow (500 отверстий + 100 слотов)
- ✅ Эффективность использования памяти
- ✅ Производительность на реальных файлах
- ✅ Масштабируемость генерации G-code
- ✅ Стресс-тесты (5000 отверстий, 20 инструментов)

**Запуск:**
```bash
# Запустить все performance тесты
pytest tests/integration/test_performance.py -v -m slow

# Запустить быстрые тесты (без медленных)
pytest tests/integration/test_performance.py -v -m "not slow"
```

## Запуск всех интеграционных тестов

```bash
# Все интеграционные тесты
pytest tests/integration/ -v

# Только быстрые тесты (без slow и gui)
pytest tests/integration/ -v -m "not slow and not gui"

# С покрытием кода
pytest tests/integration/ -v --cov=core --cov=ui --cov-report=html

# С подробным выводом
pytest tests/integration/ -v -s
```

## Маркеры pytest

- `@pytest.mark.gui` - тесты, требующие Tkinter (автоматически пропускаются если GUI недоступен)
- `@pytest.mark.slow` - медленные тесты (> 1 секунды)

## Требования

### Основные зависимости:
- pytest >= 7.0.0
- pytest-cov (для покрытия кода)

### Опциональные зависимости:
- tkinter (для UI тестов)

## Тестовые данные

Тесты используют файлы из каталога `Samples/`:
- `Материнка универсальная-RoundHoles.TXT` - отверстия
- `Материнка универсальная-SlotHoles.TXT` - слоты
- `Материнка универсальная_Profile.gbr` - контур платы

Performance тесты генерируют временные файлы автоматически.

## Статистика тестов

### Текущее покрытие:
- **Unit-тесты:** 270 тестов
- **Интеграционные тесты:** 40+ тестов
- **Общее покрытие:** ~85%

### Время выполнения:
- End-to-End тесты: ~5 секунд
- UI тесты: ~3 секунды
- Performance тесты (быстрые): ~2 секунды
- Performance тесты (медленные): ~30 секунд
- **Всего:** ~40 секунд

## Примеры использования

### Запуск конкретного теста:
```bash
pytest tests/integration/test_full_workflow.py::TestExcellonToGCodeWorkflow::test_excellon_to_gcode_basic_workflow -v
```

### Запуск с фильтром по имени:
```bash
pytest tests/integration/ -v -k "workflow"
```

### Запуск с остановкой на первой ошибке:
```bash
pytest tests/integration/ -v -x
```

### Запуск с параллельным выполнением (требует pytest-xdist):
```bash
pytest tests/integration/ -v -n auto
```

## Отладка тестов

### Включить подробный вывод:
```bash
pytest tests/integration/ -v -s --tb=long
```

### Запустить только упавшие тесты:
```bash
pytest tests/integration/ --lf
```

### Профилирование тестов:
```bash
pytest tests/integration/ --durations=10
```

## CI/CD интеграция

Интеграционные тесты автоматически запускаются в CI/CD pipeline:

```yaml
# Пример для GitHub Actions
- name: Run integration tests
  run: |
    pytest tests/integration/ -v -m "not slow and not gui" --cov=core --cov=ui
```

## Добавление новых тестов

1. Создайте новый файл `test_*.py` в каталоге `tests/integration/`
2. Используйте существующие фикстуры из `conftest.py`
3. Добавьте соответствующие маркеры (`@pytest.mark.gui`, `@pytest.mark.slow`)
4. Обновите эту документацию

## Известные проблемы

- UI тесты могут не работать в headless окружении (без X11/Wayland)
- Performance тесты могут давать разные результаты на разных машинах
- Некоторые тесты требуют наличия тестовых файлов в каталоге `Samples/`

При возникновении проблем с тестами создайте issue в репозитории проекта.
